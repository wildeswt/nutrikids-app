# Internacionalización (`apps/mobile`, RT-10)

Código: `apps/mobile/src/i18n/` (configuración, formatos, idioma), `src/components/LanguageSelector.tsx`.
Librerías: `i18next`, `react-i18next`, `expo-localization`.

Idiomas: **español (`es`)**, idioma base y de respaldo, y **kichwa (`qu`)**, que hoy es un
**borrador de traducción automática** pendiente de revisión por hablantes nativos (ver
[`locales/qu/README.md`](../apps/mobile/src/i18n/locales/qu/README.md)).

## Archivos de traducción

Cada idioma tiene una carpeta con un JSON por área de la app (_namespace_):

```
apps/mobile/src/i18n/locales/
  es/  common.json  auth.json  caregiver.json  consent.json  professional.json  errors.json
  qu/  (mismos archivos, valores en kichwa)
```

| Namespace      | Contenido                                                                |
| -------------- | ------------------------------------------------------------------------ |
| `common`       | Acciones, marca, roles, especialidades, unidades, edades, fechas, idioma |
| `auth`         | Bienvenida, selección de perfil, login, registro, recuperar contraseña   |
| `caregiver`    | Vistas del cuidador (inicio, control, evolución, mensajes, perfil)       |
| `consent`      | Pantalla de consentimiento y documento legal versionado                  |
| `professional` | Vistas del profesional de salud                                          |
| `errors`       | Mensajes de error de la API y de la app                                  |

Cada texto tiene una **clave**, que es igual en todos los idiomas; solo cambia el valor:

```json
// es/caregiver.json
"home": { "greeting": "¡Hola, {{name}}!" }

// qu/caregiver.json
"home": { "greeting": "¡Imanalla, {{name}}!" }
```

`src/i18n/resources.ts` importa los archivos y registra los idiomas (`es`, `qu`), las opciones
del selector (`LANGUAGE_OPTIONS`) y el locale usado por `Intl` en cada idioma.

## Inicio de la app

1. **Configuración** (`src/i18n/index.ts`): i18next se inicia de forma síncrona con los textos
   incluidos en la app (sin descargas). El idioma inicial sale del teléfono
   (`expo-localization`); si no es un idioma soportado, se usa español.
2. **Preferencia guardada** (`src/i18n/language.ts`): `RootLayout` llama a
   `restoreLanguagePreference()`. Si la persona ya eligió un idioma en el selector, se recupera
   del almacenamiento del teléfono (`expo-secure-store`, clave `nutrikids.language`) y se aplica.

## Uso en componentes

Los componentes no escriben textos fijos: piden una clave.

```tsx
const { t } = useTranslation(['caregiver', 'common']);

<Text>{t('home.greeting', { name: caregiverName })}</Text>;
<Text>{t('common:actions.back')}</Text>;
```

- Sin prefijo, la clave se busca en el primer namespace de la lista (`caregiver`). Con prefijo
  (`common:`) se busca en ese namespace.
- Fuera de componentes (librerías, errores de la API, hooks) se usa la instancia global:
  `i18n.t('errors:network')`.
- Las claves están tipadas (`src/i18n/i18next.d.ts`): una clave mal escrita hace fallar
  `pnpm --filter mobile typecheck`.

### Variables, plurales y respaldo

- **Variables**: `{{name}}`, `{{count}}`, `{{date}}`. Se traduce la frase; el dato se inserta tal
  cual. No se deben traducir ni renombrar dentro de los JSON.
- **Plurales**: sufijos `_one` / `_other` (`"years_one": "{{count}} año"`,
  `"years_other": "{{count}} años"`). i18next elige la forma según `count`. En kichwa ambas
  formas son iguales ("3 wata"), porque el sustantivo no cambia después de un número.
- **Respaldo**: si falta una clave en `qu`, se muestra la versión en español. Así funciona el
  documento legal del consentimiento, que se muestra en español con un aviso.

## Fechas, edades y números

`src/i18n/format.ts` arma los valores con piezas de los archivos de traducción:

| Función                | Español               | Kichwa              |
| ---------------------- | --------------------- | ------------------- |
| `formatAge(41)`        | 3 años y 5 meses      | 3 wata 5 killa      |
| `formatAgeShort(39)`   | 3 años 3m             | 3 wata 3k           |
| `formatLongDate(...)`  | 18 de octubre de 2026 | 18 wayru killa 2026 |
| `formatShortDate(...)` | 16 oct                | 16 wayru            |
| `formatDecimal(12.2)`  | 12,2                  | 12,2                |

- Los **nombres de los meses** salen de `common.json` → `date.months` / `date.monthsShort`, no del
  teléfono: los teléfonos no traen meses en kichwa de Ecuador (sus datos de `qu` son de quechua
  de Perú).
- **Fechas numéricas, horas y decimales** usan `Intl` con el locale de
  `INTL_LOCALE_BY_LANGUAGE` (`es` → `es`, `qu` → `es-EC`).

## Cambio de idioma

`LanguageSelector` (pantalla de bienvenida, perfil del cuidador y perfil del profesional) llama
a `changeAppLanguage('qu' | 'es')`, que:

1. Cambia el idioma de i18next. Todos los componentes que usan `useTranslation`, incluidos los
   layouts de pestañas y del menú lateral, se vuelven a dibujar con los textos nuevos.
2. Guarda la elección en el teléfono para el próximo inicio.

Los idiomas se muestran con su propio nombre ("Español", "Kichwa"). Si un idioma está marcado
como `draft: true` en `LANGUAGE_OPTIONS`, el selector avisa que la traducción está en revisión.

## Qué no se traduce

- **Códigos que manda la API** (`nutrition`, `CAREGIVER`, `STANDING`): la app los convierte en
  texto con sus archivos, por ejemplo `t('common:specialties.nutrition')`.
- **Datos de la base**: nombres propios (niños, profesionales, centros de salud) y textos
  escritos por personas (mensajes, notas) se muestran tal como vienen. Mientras las pantallas
  no estén conectadas a la API, esos datos de ejemplo viven en `src/constants/demo-data.ts`.
  Una traducción automática de mensajes, si se hace, debe ir en el backend, sin modificar los
  originales, y revisando antes el consentimiento: implica enviar datos de salud a un tercero.
- **Documentos legales versionados** (`consent.json` → `documents.<versión>`): el texto de una
  versión publicada no cambia. Para modificarlo se crea una nueva versión (`v2`) y se actualiza
  `CURRENT_CONSENT_VERSION` en `src/lib/consent-api.ts`. Solo se agrega en otro idioma con una
  traducción revisada y aprobada.

## Flujo resumido

```
teléfono / preferencia guardada ─► idioma activo (es | qu)
                                          │
componente: t('clave', { variables }) ─► locales/<idioma>/<namespace>.json
                                          │ si falta la clave
                                          ▼
                                   locales/es/<namespace>.json
                                          │
                       texto final con variables y plurales
```

## Cómo hacer cambios

- **Corregir un texto**: cambiar el valor en `es/*.json` (y en `qu/*.json` si corresponde). No
  hace falta tocar el componente.
- **Agregar un texto nuevo**: crear la clave en `es/<namespace>.json` (y en `qu`) y usarla con
  `t('...')`. No escribir textos fijos en los componentes.
- **Agregar un idioma**: crear `locales/<código>/` con los mismos archivos, importarlos y
  registrarlos en `resources.ts`, y agregar la opción en `LANGUAGE_OPTIONS`.
- **Vistas del cuidador**: usar lenguaje sencillo, con frases cortas, segunda persona (tú) y sin
  siglas sin explicar (por ejemplo "IMC (peso y estatura juntos)").

## Tests

- `src/__tests__/i18n.test.ts`: el español está completo y sin valores vacíos; cada archivo de
  `es` está registrado; `qu` tiene todas las claves de `es` (salvo `documents.*`) y ninguna
  clave desconocida; respaldo al español; formatos de edad, fecha y número.
- `src/__tests__/language-selector.test.tsx`: opciones del selector, cambio a kichwa, aviso de
  borrador, guardado y recuperación de la preferencia, fechas en kichwa.
- `src/__tests__/setup.ts`: inicia i18n en español para todos los tests (simula
  `expo-localization`).
