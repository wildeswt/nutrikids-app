# Internationalization (`apps/mobile`, RT-10)

Code: `apps/mobile/src/i18n/` (setup, formatting, language preference),
`src/components/LanguageSelector.tsx`. Libraries: `i18next`, `react-i18next`, `expo-localization`.

Languages: **Spanish (`es`)**, the base and fallback language, and **Kichwa (`qu`)**, currently a
**machine-translated draft** pending review by native speakers (see
[`locales/qu/README.md`](../apps/mobile/src/i18n/locales/qu/README.md)).

## Translation files

Each language has a folder with one JSON file per app area (_namespace_):

```
apps/mobile/src/i18n/locales/
  es/  common.json  auth.json  caregiver.json  consent.json  professional.json  errors.json
  qu/  (same files, Kichwa values)
```

| Namespace      | Content                                                                         |
| -------------- | ------------------------------------------------------------------------------- |
| `common`       | Actions, brand, roles, specialties, relationships, units, ages, dates, language |
| `auth`         | Welcome, profile selection, login, sign-up, password recovery                   |
| `caregiver`    | Caregiver screens (home, add child, checkup, evolution, messages, profile)      |
| `consent`      | Consent screen and the versioned legal document                                 |
| `professional` | Health professional screens                                                     |
| `errors`       | API and app error messages                                                      |

Every text has a **key** that is the same in all languages; only the value changes:

```json
// es/caregiver.json
"home": { "greeting": "¡Hola, {{name}}!" }

// qu/caregiver.json
"home": { "greeting": "¡Imanalla, {{name}}!" }
```

`src/i18n/resources.ts` imports the files and registers the languages (`es`, `qu`), the selector
options (`LANGUAGE_OPTIONS`) and the `Intl` locale used for each language.

## App start-up

1. **Setup** (`src/i18n/index.ts`): i18next is initialized synchronously with the texts bundled in
   the app (nothing is downloaded). The initial language comes from the device
   (`expo-localization`); an unsupported language falls back to Spanish.
2. **Saved preference** (`src/i18n/language.ts`): `RootLayout` awaits `restoreLanguagePreference()`
   before rendering any screen (it shows the loading view meanwhile). If the user picked a
   language in the selector, it is read from device storage (`expo-secure-store`, key
   `nutrikids.language`) and applied, so a saved Kichwa preference never flashes Spanish.

## Usage in components

Components never hard-code UI text; they ask for a key.

```tsx
const { t } = useTranslation(['caregiver', 'common']);

<Text>{t('home.greeting', { name: caregiverName })}</Text>;
<Text>{t('common:actions.back')}</Text>;
```

- Without a prefix, the key is looked up in the first namespace of the list (`caregiver`). With a
  prefix (`common:`) it is looked up in that namespace.
- Outside components (libraries, API errors, hooks) use the global instance:
  `i18n.t('errors:network')`.
- Keys are typed (`src/i18n/i18next.d.ts`): a misspelled key fails
  `pnpm --filter mobile typecheck`.
- Layouts (`(caregiver)/_layout.tsx`, `(professional)/_layout.tsx`) also use `useTranslation`, so
  tab and drawer titles update when the language changes. Their tests call the layout inside a
  render (hooks need one).

### Variables, plurals and fallback

- **Variables**: `{{name}}`, `{{count}}`, `{{date}}`. The sentence is translated; the value is
  inserted as is. Never translate or rename them inside the JSON files.
- **Plurals**: `_one` / `_other` suffixes (`"years_one": "{{count}} año"`,
  `"years_other": "{{count}} años"`). i18next picks the form from `count`. In Kichwa both forms are
  the same ("3 wata"): the noun does not change after a number.
- **Fallback**: a key missing in `qu` is shown in Spanish. This is how the consent legal document
  works: it is shown in Spanish with a notice.

## Dates, ages and numbers

`src/i18n/format.ts` builds these values from pieces in the translation files:

| Function               | Spanish               | Kichwa              |
| ---------------------- | --------------------- | ------------------- |
| `formatAge(41)`        | 3 años y 5 meses      | 3 wata 5 killa      |
| `formatAgeShort(39)`   | 3 años 3m             | 3 wata 3k           |
| `formatLongDate(...)`  | 18 de octubre de 2026 | 18 wayru killa 2026 |
| `formatShortDate(...)` | 16 oct                | 16 wayru            |
| `formatDecimal(12.2)`  | 12,2                  | 12,2                |

- **Month names** come from `common.json` → `date.months` / `date.monthsShort`, not from the
  device: phones have no Ecuadorian Kichwa month names (their `qu` data is Peruvian Quechua).
- **Numeric dates, times and decimals** use `Intl` with the locale from `INTL_LOCALE_BY_LANGUAGE`
  (`es` → `es`, `qu` → `es-EC`).
- `formatChildAge(birthDate)` in `src/lib/children-api.ts` delegates to `formatAge`.

## Changing the language

`LanguageSelector` (welcome screen, caregiver profile and professional profile) calls
`changeAppLanguage('qu' | 'es')`, which:

1. Changes the i18next language. Every component using `useTranslation`, including the tab and
   drawer layouts, re-renders with the new texts.
2. Saves the choice on the device for the next launch.

Languages are shown by their own name ("Español", "Kichwa"). If a language is marked
`draft: true` in `LANGUAGE_OPTIONS`, the selector warns that the translation is under review.

## What is not translated

- **Codes sent by or to the API** (`nutrition`, `CAREGIVER`, `STANDING`, `MOTHER`): the app turns
  them into text with its own files, e.g. `t('common:specialties.nutrition')`.
  - **Relationship** (`add-child.tsx`): the API receives the stable codes `MOTHER`, `FATHER`,
    `LEGAL_GUARDIAN` (`RELATIONSHIP_OPTIONS` in `src/lib/child-form.ts`), never a translated label,
    so the stored value does not depend on the app language. `relationshipLabel(value)` also maps
    legacy Spanish values already stored (`madre`, `Padre`, `Tutor Legal`) to the translated label.
- **Database data**: proper names (children, professionals, health centers) and text written by
  people (messages, notes) are shown as they come. While screens are not connected to the API,
  that sample data lives in `src/constants/demo-data.ts`. If messages are ever machine-translated,
  it must happen in the backend, without changing the originals, and only after reviewing the
  consent: it means sending health data to a third party.
- **Server error messages** (`err.message` from the API / shared Zod schemas) are in Spanish and
  are shown as received; translating them needs error codes in the API responses.
- **Versioned legal documents** (`consent.json` → `documents.<version>`): the text of a published
  version never changes. To change it, create a new version (`v2`) and update
  `CURRENT_CONSENT_VERSION` in `src/lib/consent-api.ts`. Add it in another language only with a
  reviewed and approved translation.

## Flow summary

```
device / saved preference ─► active language (es | qu)
                                     │
component: t('key', { variables }) ─► locales/<language>/<namespace>.json
                                     │ if the key is missing
                                     ▼
                              locales/es/<namespace>.json
                                     │
                    final text with variables and plurals
```

## Making changes

- **Fix a text**: change the value in `es/*.json` (and in `qu/*.json` if needed). No component
  change is required.
- **Add a text**: create the key in `es/<namespace>.json` (and in `qu`) and use it with `t('...')`.
  Do not hard-code UI text in components.
- **Add a language**: create `locales/<code>/` with the same files, import and register them in
  `resources.ts`, and add the option to `LANGUAGE_OPTIONS`.
- **Caregiver screens**: use plain language — short sentences, second person (tú), and no
  unexplained acronyms (e.g. "IMC (peso y estatura juntos)").

## Tests

- `src/__tests__/i18n.test.ts`: Spanish is complete with no empty values; every `es` file is
  registered; `qu` has every `es` key (except `documents.*`) and no unknown key; Spanish fallback;
  age, date and number formats.
- `src/__tests__/language-selector.test.tsx`: selector options, switching to Kichwa, draft notice,
  saving and restoring the preference, Kichwa dates.
- `src/__tests__/child-form.test.ts`: relationship codes and legacy values.
- `src/__tests__/setup.ts`: initializes i18n in Spanish for every test (mocks `expo-localization`).
  Screen tests compare against `i18n.t('...')` instead of repeating the Spanish text.
